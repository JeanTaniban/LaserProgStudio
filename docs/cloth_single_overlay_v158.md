# LaserProg v158 — Cloth Single Overlay Workflow

This release rebuilds the Cloth interaction around one contextual viewport overlay.
The same window changes its contents and accent colour instead of stacking several
specialised overlays over the viewport.

## Main overlay

The default Cloth overlay contains exactly:

```text
Take face | Close | Draw | Properties | Apply
```

- **Take face** is enabled only when one or more logical scene-mesh surface groups
  are selected. It copies those temporary source surfaces into persistent textile
  faces.
- **Close** is enabled only when at least two textile anchors are selected. An
  anchor can be a logical textile face group or an isolated textile edge.
- **Draw** opens the manual textile drawing context.
- **Properties** opens textile-only role assignment.
- **Apply** writes the folded Cloth output and regenerates its linked flat preview,
  while keeping the tool open for continued editing.

The inspector is deliberately reduced to the smart-selection continuity control
between 0 and 1. Geometry actions live in the single overlay.

## Persistent mixed selection

The main context accepts a mixed selection throughout the workflow:

- logical surface groups on one or more scene meshes, through the public smart
  surface-selection API;
- logical textile face groups;
- isolated textile edges created in Draw.

Click replaces the selection and Shift+click adds another item. A fast double-click
in empty space clears the complete mixed selection. Camera drag is kept separate
from selection through the pointer state machine.

Logical textile groups are tracked explicitly during the interaction. A group may
contain several technical Cloth patches, but it counts as one user-facing face and
one Close anchor.

## Take face

Source mesh regions remain temporary until **Take face** is pressed. The command:

1. reads every selected logical mesh region;
2. creates the corresponding persistent Cloth geometry;
3. records source object and source-face metadata;
4. assigns a persistent logical textile-group identity;
5. clears the temporary source selection;
6. keeps the newly created textile group selected.

No point or edge gizmos are displayed during this operation.

## Close context

The overlay is replaced by an amber context:

```text
Apply | Prev | Next | Reset
```

Close consumes only persistent textile geometry:

- logical textile groups created by Take face;
- closed faces created in Draw;
- faces generated by an earlier Close;
- isolated textile edges.

For multi-patch logical groups, shared internal curves are removed and the complete
outer user-facing boundary is reconstructed before proposal generation. When
several loops remain, the longest closed loop is treated as the outer Close anchor.

The current solver produces deterministic ruled-surface proposals and keeps them
non-destructive until Apply. Prev and Next browse alternatives; Reset returns to
the main overlay without modifying the document.

## Draw context

The same overlay changes to a green context:

```text
Apply | Modify | Line | Polyline | Faces | Edges |
Smart snap | Axis guides | Clear
```

- **Line** creates an isolated textile edge.
- **Polyline** creates open edges; closing the contour automatically creates a
  textile face.
- **Modify** selects individual technical textile faces or edges, without logical
  API grouping. Delete removes the selected entities.
- **Faces / Edges** selects the unique entity type used by Modify.
- **Smart snap / Axis guides** reuse the tracing APIs used elsewhere in LaserProg.
- **Clear** cancels the active draft.
- **Apply** validates the current Draw operation and returns to the main context.

Textile vertices are rendered only in Draw. Outside Draw, the viewport shows only
textile faces and their edges.

## Properties context

The overlay changes to a violet context:

```text
Apply | Textile | Anchor | Pattern | Face | Group | Reset
```

Only persistent textile faces can be selected here. Scene meshes are ignored.

- **Face** selects one technical textile face.
- **Group** uses the public smart-selection API and selects one logical textile
  region.
- **Textile**, **Anchor** and **Pattern** remain disabled until a valid textile
  selection exists.
- **Reset** clears the properties selection.
- **Apply** keeps the role changes and returns to the main context.

Roles remain visible outside the submenu through surface colours: normal textile,
pattern and anchor/junction use distinct render layers. Selection highlighting is
separate from the persistent role colour.

## State machine

The public UX state is intentionally small:

```text
MAIN
├── CLOSE
├── DRAW
└── PROPERTIES
```

Each context owns its selectable entity types, overlay contents, accent colour,
button enablement and cancellation behaviour. Computing and preview details remain
internal and do not create additional overlay windows.

## Technical verification

Validated in this release:

- 12 dedicated v158 single-overlay and interaction tests;
- 93 focused Cloth, flattening, boolean-pipeline and smart-selection tests;
- complete Python compilation;
- Quality Gate;
- API boundary audit: 0 critical issues;
- architecture-health audit;
- migration audit: all 21 built-in tools use Creator runtimes;
- product audit: all 21 built-in tools pass.

Six pre-v158 UI suites still encode the removed interaction contract (old multiple
overlays, old button names, and a first viewport click that immediately starts a
polyline). They produce 17 expected contract failures and are not treated as v158
regressions. Their underlying geometry and pipeline coverage is retained by the
focused tests above and by the new v158 contract tests.

## Known limits

- Close currently generates deterministic ruled surfaces; collision avoidance,
  deformation optimisation and automatic optimal panel segmentation are future
  work.
- Pattern and Anchor are panel roles in this release. Local painted zones inside a
  panel and multi-layer attachment definitions are not implemented yet.
- Physical layer offsets and wood/textile attachment generators are not included
  yet.
