# Smart Surface Selection API — v154 UX state machine

## Semantic selection rules

The API operates on complete `SurfaceRegionResult` objects generated by Auto or
manual continuity. A normal selection replaces the current region:

```python
session.adopt(snapshot, region)
```

A multiple selection is built only from complete algorithmic regions:

```python
session.add_region(snapshot, another_region)
```

The session preserves the region count and exposes the combined face set. It
does not enter an exact face-editing mode.

## Pointer state machine

`SurfaceSelectionPointerMachine` isolates platform event sequencing from the
selection solver. Its states are:

- `READY`;
- `PRESSED`;
- `DRAGGING`;
- `DOUBLE_CLICK_GUARD`.

It emits only:

- `CLICK` after a press/release inside the drag threshold;
- `DOUBLE_CLICK` when the host forwards that event;
- `NONE` after a drag or for the release following a double-click.

The host tool performs picking after receiving an action. The Selection API test
uses this mapping:

- click on surface: replace with one complete logical region;
- Shift+click on surface: add one complete logical region;
- click or Shift+click in empty space: no action;
- double-click on surface: no special action;
- double-click in empty space: clear.

## Deliberately removed behaviour

v154 removes the editable automatic double-click workflow from both the public
session and the test tool. There is no automatic-to-exact mode transition and no
face-by-face editing state hidden behind double-click.
